# Улучшения (Frontend)

Дата: 2026-03-25

Этот документ фиксирует идеи и план улучшений по фронтенду внешнего сайта `ichem-site`.

## Приоритеты

### P0 — стабильность и соответствие контракту
- Добавить явные состояния `loading`/`error` для `ProductsPage` и `Services` (скелетон/сообщение вместо “пусто”).
- Привести fallback для `Services` к той же модели, что и публичный API (`category_key` / `category_description`, карточки `name` / `description`).

### P1 — единообразный UX
- Унифицировать скролл-навигацию между `Products` и `Services` (одинаковые правила “куда и насколько” скроллить, единая логика якорей/отступов).
- Добавить доступность табов `Services` (например, `role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`).

### P2 — архитектура data-layer
- Вынести data-логики (нормализация/группировка) из `Services.tsx`/`ProductsPage.tsx` в отдельные слои:
  - `src/api/*` (запросы)
  - `src/hooks/*` (хуки данных)
  - `src/types/*` (доменные типы)
  - `src/utils/*` (маппинги, форматтеры)
- Добавить кеш на уровне `useProductsCatalog`/`useServicesCatalog`, чтобы не дергать API при повторных монтированиях/переключениях.

### P3 — качество и поддерживаемость
- Привести единообразные `key` в списках к стабильным идентификаторам (сейчас в некоторых местах могут встречаться индексы/динамические значения).
- Добавить минимальные SEO-мета для `/products` и `/services` (title/description под `language`).

## Технический чек-лист для каждой интеграции API

Перед релизом после изменений backend-контракта:
- Проверить, что фронт игнорирует исчезнувшие поля (например, `features`).
- Проверить сортировки и группировки (особенно по `category_key`).
- Проверить обработку `null` (`category_description`, `pdf_url`, `photo`).
- Проверить пути ассетов через `assetUrl()` и корректность `base`/`basename`.
